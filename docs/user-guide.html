01

Quick start

  1. Double-click AI Usage Dashboard.html. It opens as a file:// page; no server is needed.
  2. Use Chrome or Edge for the full experience. Only the folder picker needs the File System Access API; dropping files works everywhere, and other browsers fall back to the classic folder chooser automatically. ZIP imports and Bedrock signing rely on DecompressionStream and WebCrypto, which current Chromium browsers provide on file:// pages.
  3. In the accounts hub at the top, click Connect on a card and follow its instructions:
    • Local collector (automatic): run node docs/tools/ai-usage-collector.mjs once and every tool it finds connects by itself, no folder picking: Claude Code and Cowork, Codex CLI, Copilot CLI, Gemini CLI, Continue, Cline, Roo, Kilo Code, Junie, OpenCode, Goose, Devin CLI, Amp, Zed, LM Studio, Ollama and Jan. See Automatic mode.
    • Claude Code / Desktop: pick your .claude folder and, for Cowork (the desktop app's agent sessions), the Claude app's data folder, or let the collector find both. Exact tokens for every session.
    • Anthropic API / OpenAI API: paste an Admin key for exact usage plus billed cost.
    • Poe: paste a Poe API key for exact tokens per bot and Poe's own dollar figure per query.
    • Any coding tool that writes logs (Codex CLI, Copilot CLI, Cline, Continue, Gemini CLI, Roo, Kilo Code, Aider, Junie, OpenCode, Goose, Devin CLI, Amp, Zed): pick its log folder. Cursor exports a usage CSV instead; drop it on Imports.
  4. Folder choices, imported data and settings are remembered in the browser's storage for this file. API keys are kept only if you tick Remember key on this computer, and cloud tokens never. Folder sources re-scan on demand or on a timer with Auto re-scan.

The page is a single static file. Copy it anywhere, keep it on a USB stick, or open it in a private window if you want nothing remembered.

1b

Automatic mode: the local collector

A file:// page cannot read your disk on its own, which is why every folder-based card asks for a folder pick. The local collector removes that step. It is an optional, zero-dependency Node script (Node 20 or newer) that finds the standard log folders of the AI tools on this machine and serves them, read-only, to the dashboard on 127.0.0.1. Without it nothing changes; with it, every tool it finds shows up connected and stays current by itself.

Start it (leave the terminal open; Ctrl+C stops it): 
node docs/tools/ai-usage-collector.mjs
It prints one line per tool, then the token and a ready-made URL: 
Token: <64 hex characters>
Open the dashboard: http://127.0.0.1:11436/?token=<token>
listening on http://127.0.0.1:11436

The token is created on the first run and kept in ~/.ai-usage/collector.token (%USERPROFILE%\.ai-usage\collector.token on Windows); later runs reuse it.

Use it, two ways

  1. Open the printed URL. The collector serves the dashboard itself, so page and collector share one origin. The token is taken from the URL into the Local collector (automatic) card (first card in Coding tools) and removed from the address bar; click Validate & connect. Nothing to paste.
  2. Keep your file:// copy. Open the Local collector card, paste the token from the terminal or the token file, tick Remember token on this computer if you want it kept, and click Validate & connect. The Collector URL defaults to http://127.0.0.1:11436; if you started with --port, change it to the printed URL.

Either way, each tool the collector finds connects under its own card, labelled N files · via collector, with exactly the rows, project rows and re-scan cache a folder pick would produce. The collector card shows N tools · M files · checked <time> and a table of every tool it looked for: root folder, file count (or not found / found, nothing to read) and the newest change.

Automatic refresh

  • The collector watches every found folder with the operating system's file watcher; a change marks that tool for a re-walk on its next status request. Where recursive watching is unavailable, that tool is re-walked when its counts are older than 30 s and the startup table says watch polling.
  • While the collector card is connected, the dashboard asks it for status every 60 s (skipped while the tab is hidden) and re-reads only the tools whose file count or newest change moved. Unchanged files hit the scan cache, so a tick with nothing new costs one small request. Refresh all runs one check now; a tool card's Re-scan / Sync goes through the collector while it feeds that card.
  • After a reload the watch resumes by itself only if the token was remembered; otherwise the card says Reconnect and the tools' stored data stays on screen until you paste the token again.
  • Disconnect on the collector card forgets the token and stops the watch; the tools keep their entries and data. Disconnecting a tool's own card while the collector feeds it takes that tool out of the collector's reads until you click Validate & connect on the collector card again.

Security

  • Binds 127.0.0.1 only; nothing is reachable from other machines.
  • Every /api/* request needs the token in the Authorization: Bearer … header, otherwise 401; a ?token= query is refused on the API (the ?token= in the printed URL only pre-fills the card and is removed from the address bar). Without the token, any web page open in your browser could read the machine's AI transcripts through the port; the origin is deliberately not the gate, because a file:// page and a sandboxed iframe both have a null origin. Only Host: 127.0.0.1, localhost or [::1] is answered; anything else gets 421.
  • Read-only, and only inside the discovered roots or the --root folders: paths with .., absolute paths and symbolic links are refused. Only usage-log file types are listed or served (.jsonl, .json, .md, .sqlite, .db, .csv, .txt), and never a file whose name says credential, oauth, token, secret, password or api key, nor .env*, auth.json, settings.json, config.json, mcp.json or .claude.json; the token file is never listed or served. The walk skips node_modules, .git and checkpoints, a tool's own non-log folders (OpenCode's snapshot, bin, log, cache) and, under a Cowork root, the files a session handled (outputs, uploads, uploads-tmp, .project-cache, session-env, backups); those are never listed or served either.
  • The collector logs one line per request (method, path, status, bytes), never file contents and never the token. The page sends the token only to the Collector URL on the card, as a header, and stores it only with Remember token on this computer. Every request the page makes times out after 30 s.
  • GET /api/file?…&decode=zstd hands the page a Zed threads.db with its zstd rows decoded (one JSON line per thread) when the browser cannot decompress zstd itself. It is offered for the zed tool only, gated and path-checked like every other file request, and the decoded bytes are never written to disk.
  • What lands in the browser is exactly a folder pick's result: aggregated tokens per day, platform and model, no message text.

Two copies, two storages. The page the collector serves (http://127.0.0.1:11436) and your file:// copy are different origins, so each keeps its own browser storage: folder choices, imports, remembered keys and settings do not carry over. Pick one and stick with it, or export a CSV backup before switching.

Tidying the hub

  • ✕ on a card hides it. A "N hidden — show" chip brings everything back. A hidden card un-hides itself when it becomes connected.
  • Each group header collapses with ▾. With more than 12 visible cards a Search accounts… box appears.
  • Show legacy source cards reveals the older per-source panels below the charts (the same panels the Manage dialog shows). Cards that read both a server and a folder (Ollama, Jan, text-generation-webui) show two status lines and a Re-scan button for the folder half.
  • Keyboard: cards are focusable; hiding, collapsing and closing a dialog keep focus where you were.
  • ? Help in the toolbar (or the ? key outside a text field) opens a condensed version of this guide inside the dashboard: start here, the badge legend, where the numbers come from (one line per honesty class: exact, estimated, validate-only, link-only, experimental), how prices work, six fixes, keyboard, and links back to this page.

05

Reading the dashboard

  • Date range: 7 / 30 / 90 days, month to date, all, or a custom range. Provider data is bucketed by UTC day; local logs by your local day.
  • Cost vs Tokens switches every chart; By platform / By model switches the series. Click a platform chip to hide it; when more than 12 platforms have data the rest fold into one "Other". A drill-down narrows everything to one platform until you clear it.
  • KPIs: tokens, output tokens, messages / requests, API-equivalent cost (list prices from the editable price list) and Actual billed (from APIs), each with a delta against the previous period and a sparkline. Actual billed comes only from sources that report real dollars: Anthropic, OpenAI, OpenRouter, Fireworks, DeepSeek export, Cursor export with cost, GitHub Copilot billing, Azure, Vertex, Bedrock, Claude Enterprise, Poe, DeepInfra, the Alibaba bill CSV, an OpenRouter key behind the OpenAI-compatible card, and a generic CSV with a cost_usd column. A billed figure marked stale means the last cost fetch failed and the old number is still shown. The line under the KPIs says which price set priced the figures, prices: bundled set of <date> plus the number of your own edits, and the CSV export's first line carries the same provenance.
  • Daily usage stacks by platform or model; wide ranges bucket to weeks or months. Hover for exact numbers; click a legend entry to hide that series; Table lists the same series day by day.
  • By model, Platform share, Model breakdown (input / cache write / cache read / output / cost per model, with est. marks, a fallback price badge where no row knows the model and a priced as <successor> badge where a retired id is billed as its successor) and Projects (from Claude Code, Codex, Gemini CLI, Copilot CLI and Junie logs).
  • Cowork, reported vs estimated: when the window holds Cowork sessions, the Claude Code / Desktop card shows Anthropic's own figure for Cowork, the total_cost_usd each session's audit.jsonl records, next to our list-price estimate for the same sessions and days; sessions without an audit record are counted and disclosed. The figure is never added to Actual billed: a flat plan is not a bill.
  • Insights, seven tiles: month-to-date and projected spend, a 13-week activity heatmap, week over week, cache savings, busiest hours (last 90 days of hourly detail), model efficiency (models with at least 20 messages), top project movers. Each tile has a ✕ to hide it; a chip above the row brings it back.
  • This period in AI summarises the period in plain sentences.
  • Budgets: a total and per-platform monthly limit; the editor lists the platforms you actually use. Alerts appear at 80 %, at 100 % (only when spend has really reached the limit) and when the projection overruns; dismiss per month. Hub cards show a budget bar.
  • API price list: per-million prices per model pattern, grouped by vendor. Each group header reads <vendor> · N rows · M matched your data (and K overridden by a platform rate where that applies); the groups your data lands on open first, matched rows first within them, and a closed group builds its rows when you open it. Every row shows its provenance: verified <date> with a confidence pill and a link to the source page, unverified since Aug 2026 for a row carried over without a re-check, your edit with a user pill for yours. The banner above the list reads Prices verified <date> — N days ago and turns amber past 90 days. Platform overrides, a host's own rate for a model it bills differently from the vendor (Groq, DeepInfra, SambaNova, Together AI, Cerebras), are a read-only group at the bottom and win over the vendor row for data from that platform; the vendor row then says wins for <platform>: $X in / $Y out, so an edit of that row changes nothing for that platform's data. Retired model ids are priced as their successor. Edit, add (+ Add model, into a "Your rows" group) or reset; edits are stored in this browser only. Patterns match a normalised id (dots to hyphens, family-first for Claude 4+, vendor prefixes and date suffixes stripped), so claude-opus-4.1, claude-4.1-opus and anthropic.claude-opus-4-1-20250805-v1:0 all hit the Opus row.
  • Unpriced models: a model id that matches no price row is priced at the catch-all "Unknown model" row ($3 in / $15 out per million by default), and the dashboard says so rather than guessing silently. A notice above the KPIs names the models with their messages and guessed cost; a second sentence names the models priced from an unverified or user-edited row ("… so its cost is an estimate"), and when only those exist the notice is informational rather than a warning. Set prices jumps to the price list, Dismiss hides the notice until a new model joins the set. The Model breakdown marks fallback rows with a fallback price badge, and "This period in AI" states how much of the figure is a fallback guess. Totals are unchanged; the point is disclosure. Local runners are $0 and never flagged.
  • Export CSV writes the rows currently in view (the selected range, minus hidden platforms) with the API-equivalent cost per row. Print report produces a clean paper layout: collapsed sections re-appear; the hub, data-source panels, budgets editor, price list and buttons are left out. ◐ Theme toggles light/dark.
  • ↻ Refresh re-syncs every connected source; Auto re-scan does it every 5 / 15 / 60 minutes (remembered keys only; session-only tokens re-sync while they are still pasted).

Each major section header has a ▾ to collapse it; collapses are remembered and ignored when printing.

06

How costs are computed

API-equivalent cost = tokens × the list price for that model, split into input, cache write, cache read and output. It is what the same usage would cost on the vendor's API: useful for comparing plans, not an invoice. Prices are the currently loaded list prices (the bundled set of the date the banner shows, plus your edits); historical price changes are not applied to older rows.

Actual billed comes only from vendors that report money; the two figures are always shown separately. Anthropic's own Cowork figure is shown beside our estimate on the Claude Code card and is never counted as billed.

  • Rows from estimated sources are marked est. everywhere and never mix silently with exact ones.
  • validate-only cards add no rows and no dollars; a balance in the label is the most they show. Experimental figures (the Z.ai and MiniMax quota endpoints, reverse-engineered) live in that card's status line only and never feed rows, billed amounts or totals.
  • Where a vendor reports months, not days (DeepInfra), the month's tokens and cost land on the month's first day, so day and week views show whole months on the 1st; the card says so.
  • Local runners are $0, and coding-tool requests that name a local backend (Continue + Ollama, Cline / Roo / Kilo + LM Studio, Aider ollama_chat/…, Codex OSS models, OpenCode / Goose / Zed on a local provider) are $0 too.
  • Flat-rate plans (ChatGPT, Copilot, Claude.ai, Cursor) show the list-price equivalent so you can see what the plan is worth; the card says so. Devin's ACUs and Amp's credits stay in the scan metadata and are never turned into dollars.
  • Parsers written from published code or docs rather than real files (OpenCode, Goose, Devin CLI, Kilo Code, Amp, Zed, Cody, the Cerebras and Alibaba CSV importers, DeepInfra's usage payload) say source-based, not yet verified on real files on their card.
  • No card claims to read a consumer chat product through your web login. If a vendor offers nothing, the card says no data and links you to their page.
07

Privacy and security

  • The page makes network requests only when you click Validate / Fetch / Sync (or enable auto-refresh), and only to the vendor whose key you pasted.
  • API keys are kept in the browser's storage only if you tick "Remember key on this computer". Cloud tokens and secrets (Azure, Vertex, Bedrock) are never stored.
  • Folder access uses the browser's folder picker; files are read locally and never uploaded. Only aggregated rows (day, platform, model, token counts) are stored, not message text.
  • With the local collector the files are read by that Node process on this machine and fetched by the page from 127.0.0.1 over a token-gated, read-only API: the token travels in a header only, the collector lists and serves only usage-log file types and never a credential file by name, and under a Cowork root it never touches the files a session handled (outputs, uploads, .project-cache, …). Still nothing leaves the machine, and the same aggregated rows are all that is stored.
  • Keys go to their vendor's host and nowhere else: the Alibaba card accepts an *.aliyuncs.com base URL only, the OpenAI-compatible card accepts http:// for localhost only, and the Z.ai / MiniMax quota probes are sent only after the key validated.
  • Clear stored data… (Data sources section) wipes everything the page remembered. Disconnect asks whether to keep or delete a source's data.
  • If the browser's storage is full the page says so in a banner; export a CSV backup, then clear.

09

The Ollama usage logger

Ollama keeps no usage history, so exact per-request counts exist only inside each API response. docs/tools/ollama-usage-logger.mjs is a zero-dependency Node proxy: run it, point your clients at it instead of Ollama, and it appends one JSONL line per completed request with the exact counts.

node docs/tools/ollama-usage-logger.mjs

Then set OLLAMA_HOST=127.0.0.1:11435 (or base_url=http://127.0.0.1:11435/v1 for OpenAI SDKs) and pick the logger's folder (~/.ai-usage by default) in the Ollama card, or run the local collector, which finds ~/.ai-usage by itself. Environment: LOG_PORT, OLLAMA_URL, USAGE_LOG. Counts are read from the last 64 KB of each response, so a stream of any size is logged as cheaply as a small one. OpenAI-style streaming clients must set stream_options.include_usage, or the server sends no usage object; the proxy then logs nothing and prints a warning. Nothing is ever estimated.
