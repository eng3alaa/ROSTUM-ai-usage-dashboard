## Design decisions

1. **Size gate 600 KB → 800 KB.** Plan 9 adds ≈150 KB (251 price rows, ≈35 cards, ≈8 parsers). The product stays one file; 800 KB still opens instantly from disk. `tests/checks/95-ui-misc.mjs` postRun and `.github/workflows/tests.yml` enforce the new number. The build-from-parts split is booked as Plan 10, not done here.
2. **Price data stays inline but is generated.** `tests/tools/sync-prices.mjs` renders the JSON into the HTML between the markers `/* PRICES:BEGIN (generated by tests/tools/sync-prices.mjs — edit the JSON, not this block) */` and `/* PRICES:END */`: `const PRICES_VERIFIED_ON = '2026-10-15';`, `const DEFAULT_PRICES = [...]` (row shape `{pat,label,in,out,cw,cr}` + `v` (vendor) + `at` (verified_on) + `c` (confidence) + `src` (source_url)), `const PRICE_OVERRIDES = [{platform, pat, label, in, out, cw, cr}]`, `const MODEL_ALIASES = { 'retired-id': 'successor-id', … }`. A check asserts the HTML block equals a fresh render (drift guard).
3. **Resolution order** in `Pricing.resolve(model, platform)`: (a) lowercase + `normalizeModelId`; (b) alias map → successor id (and remember `aliasOf` so the UI can say "priced as X"); (c) if `platform` has an override whose `pat` matches → that row; (d) DEFAULT_PRICES first match; (e) `.*` fallback (unchanged disclosure). `Pricing.cost(model, t)` passes `t.platform`. User-edited price lists (LS `prices`) keep working: the editor stores rows only; overrides/aliases are constants.
4. **Price-list UI at 251 rows:** grouped by vendor (collapsible, counts), each row shows `verified <date>` and a confidence pill, rows that matched the user's own data are marked and listed first within the group; a banner "Prices verified <date> — N days ago" turns amber past 90 days; "fallback price" and "priced as <successor>" badges in the Model breakdown.
5. **Cowork:** the `local` tool gains a second root — `%APPDATA%\Claude\local-agent-mode-sessions` (`~/Library/Application Support/Claude/…`, `~/.config/Claude/…`; 3P edition `%LOCALAPPDATA%\Claude-3p`) — in the collector's discovery table and in the Claude Code card copy ("pick `.claude` and, for Cowork, the Claude app folder"; both land under the same `local` source; the collector handles both roots). Transcripts parse with the existing Claude parser (same `message.usage`). `audit.jsonl` result lines (`total_cost_usd`, `modelUsage`) are summed per day into `Store.sources.local.meta.reported = {days: {d: usd}}` and shown on the card/status as "Anthropic's own figure for Cowork: $X (list-price estimate $Y)" — never into Actual billed (a flat plan is not a bill).
6. **Generic OpenAI-compatible card** (`openai-compatible`, kind api-key with a base-URL field): GET `/v1/models` validates; it then fingerprints OpenRouter (`/api/v1/key` → credits/usage), LiteLLM (`/key/info`), vLLM (`/metrics`) and says which; otherwise validate-only. Covers every vendor and self-hosted server not listed.
7. **Card kinds follow the table.** P1 exact/gated cards get data; validate-only cards validate; link-only cards say why. `v0` (CORS-blocked) is link-only with the collector-proxy note; Lambda is omitted (discontinued, no page to link); `lambda` is recorded in the spec as intentionally excluded.
8. **Zed threads are zstd-compressed.** Feature-detect `DecompressionStream('zstd')`; when unavailable the collector decompresses (`zlib.zstdDecompressSync`, Node ≥ 22.15) behind `GET /api/file?…&decode=zstd`, and the Zed card says "needs the local collector on this browser".
9. **Honesty labels:** DeepInfra usage is `exact (gated)` — the card tries `/payment/usage` and downgrades itself to validate-only with the reason when the key is refused; Z.ai / MiniMax quota endpoints are marked **experimental** (reverse-engineered) and never feed totals; Cursor's local database has no real token counts, so the Cursor card is an export-file front door for the CSV (team Admin API = collector-only note).
