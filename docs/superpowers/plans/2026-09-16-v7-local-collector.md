# AI Usage Dashboard v7 — Local Collector (automatic folder sources) — Design + Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every folder-based source automatic. Today a `file://` page cannot read the disk on its own (browser rule), so each tool needs a folder pick. v7 adds an optional, zero-dependency Node helper — the **local collector** — that auto-discovers the standard log folders on this machine and serves them to the dashboard on `127.0.0.1`, plus one hub card that connects to it. With the collector running, every tool it finds shows up connected, stays current without prompts, and no folder picker is ever needed. Without it, nothing changes.

**Baseline:** `main` at v6 (375 checks, 491 KB). Branch `v7-collector` (`git checkout -b v7-collector main`). Conventions: the v4b plan header (`docs/superpowers/plans/2026-08-19-v4b-wave2.md`) — strict TDD with RED evidence, `ONLY=<tokens>` dev loop, full suite gate, hygiene 0 control bytes / ≤ 600 KB, explicit `git add`, one commit per task, anchors not line numbers, Node-script edits for CRLF files, `textContent`-only DOM writes.

## Design

### The helper: `docs/tools/ai-usage-collector.mjs`

- Zero-dependency Node ≥ 20 script, same style as `docs/tools/ollama-usage-logger.mjs`. `node docs/tools/ai-usage-collector.mjs` binds **127.0.0.1 only** (env `COLLECTOR_PORT`, default **11436**; `--port`).
- **Auto-discovery** (per OS; `--root <connectorId>=<path>` adds or overrides; `--no-<id>` disables): `local` → `~/.claude` (projects/); `codex` → `~/.codex` (sessions/, archived_sessions/); `copilot-cli` → `~/.copilot`; `gemini-cli` → `~/.gemini`; `continue` → `~/.continue`; `cline` → `<VS Code user dir>/globalStorage/saoudrizwan.claude-dev` and the Cursor / Windsurf / VSCodium equivalents (first that exists); `roo` → `…/rooveterinaryinc.roo-cline` and `…/kilocode.kilo-code`; `junie` → `~/.junie` and the JetBrains cache dirs containing `matterhorn` (Windows `%LOCALAPPDATA%\JetBrains`, macOS `~/Library/Caches/JetBrains`, Linux `~/.cache/JetBrains`); `lmstudio` → `~/.lmstudio/conversations` or `~/.cache/lm-studio/conversations`; `ollama` → `~/.ai-usage` (usage-logger JSONL) and the desktop app dir (`%LOCALAPPDATA%\Ollama`, `~/Library/Application Support/Ollama`, `~/.ollama`) for `db.sqlite`; `jan` → `%APPDATA%\Jan\data` / `~/Library/Application Support/Jan/data` / `~/.local/share/Jan/data`; `tgwebui` and `aider` are not auto-discovered (no fixed location) — `--root` only. A root is "found" when the directory exists.
- **Auth:** on first run the collector creates `~/.ai-usage/collector.token` (32 random bytes, hex) and prints it plus the ready-made URL `http://127.0.0.1:11436/?token=<token>`. Every `/api/*` request must carry `Authorization: Bearer <token>` (or `?token=`); otherwise `401`. Reason: without a token, any web page open in the browser could read the machine's AI transcripts through the port. Origin checks are not a substitute (sandboxed iframes have a `null` origin, like `file://` pages).
- **CORS / PNA:** every response carries `Access-Control-Allow-Origin: *` (the token is the gate, not the origin), `Access-Control-Allow-Headers: Authorization`, `Access-Control-Allow-Private-Network: true` and answers `OPTIONS` with 204 — so both a `file://` page and the collector-served page can call it.
- **API** (JSON, read-only; every path is validated to stay inside its root — `..`, absolute paths and symlinks escaping the root are rejected with 400):
  - `GET /api/status` → `{ version, home, os, startedAt, tools: [{ id, name, roots: [path…], found, files, bytes, newestMtime, scannedAt }] }`. Counts come from a cached recursive walk of each found root (refreshed at most every 30 s, or immediately with `?refresh=1`); the walk skips `node_modules`, `.git`, `checkpoints` and follows no symlinks.
  - `GET /api/list?tool=<id>` → `{ tool, root, files: [{ path (relative, forward slashes), size, mtime }] }` for ALL regular files under the tool's roots (the page applies the connector's own `patterns` / `exclude` / `siblings`; the collector never duplicates the registry).
  - `GET /api/file?tool=<id>&path=<rel>` → the file bytes, streamed (`Content-Length`, `Last-Modified`); 404 when missing.
  - `GET /` → serves `AI Usage Dashboard.html` from the repo (`../../AI Usage Dashboard.html` relative to the script, or `--html <path>`), so `http://127.0.0.1:11436/?token=…` opens a dashboard that is same-origin with the collector. (That page has its own browser storage, separate from the `file://` copy — the card copy says so.)
- Logs one line per request to stdout (method, path, status, bytes — never file contents).

### The dashboard side

- New registry entry: `{ id: 'collector', name: 'Local collector (automatic)', platform: null, category: 'coding', kind: 'collector', baseUrl: 'http://127.0.0.1:11436', keyLS: 'key:collector', keyLabel: 'Collector token', keyHint: 'printed by: node docs/tools/ai-usage-collector.mjs', quality: 'exact', qualityNote: …, paths: …, links: {docs} }` — first card in the Coding tools group. `platform: null` (it owns no rows; each tool's rows land under that tool's own connector, exactly as a folder pick would).
- `RemoteFile` (page-side shim over `/api/file`): `{ name, size, lastModified, webkitRelativePath: rel, stream() → ReadableStream that fetches lazily, text(), arrayBuffer() }` — the existing parsers only use those members, and the ScanCache signature (`path + size + lastModified`) keeps scans incremental.
- `App.connectCollector(c)`: token from the card input (Remember opt-in, like any key card; a `?token=` in the page URL pre-fills it once and is then removed from the address bar) → `GET /api/status` → for every found tool whose id is a registered folder connector: `GET /api/list`, filter by the connector's `patterns`/`exclude`/`siblings` (`collectFilesFromHandle` already has that filter — reuse its matcher), build `RemoteFile`s, then hand them to the SAME landing path a folder pick uses: `App.scanFiles(connector, files, { fromCollector: true })` for folder-log connectors, and `App.scanLocalFiles(files, { fromCollector: true })` for Claude Code (a new method extracted from the `#folder-fallback` change handler so both paths share it). Each tool card turns connected with label `N files · via collector`; its Re-scan button routes to the collector while the collector is connected. The collector card shows `N tools found · M files · checked <time>` plus a table: tool, root, files, last change.
- **Automatic mode:** while the collector is connected, `App.startCollectorWatch(c)` polls `/api/status` every 60 s (skipped while `document.hidden`); when a tool's `newestMtime` or `files` changed, that tool is re-scanned (incremental — unchanged files hit the cache). Disconnect stops the timer; the tools' data stays (their cards keep the "via collector" label until the next pick or Clear).
- Errors are honest: collector not running → "Not running at http://127.0.0.1:11436 — start it with: node docs/tools/ai-usage-collector.mjs"; 401 → "Token rejected — copy the token the collector printed"; a tool present but with 0 matching files → listed as "found, nothing to read".
- Security in the page: the token follows the key rules (never in DOM text, persisted only with Remember); all URLs are built from the card's base URL and registry ids; file names reach the DOM via `textContent`.
