What the badges mean

exact
Token counts come from the tool or vendor itself.
estimated
Tokens are estimated from text (about 4 characters per token) because the source keeps no counts; the rows carry an est. mark everywhere they appear.
validate-only
The card verifies your key, but the vendor offers no usage history to a local page. Spend lives on the vendor's usage page, linked from the card.
no data
No data path from a local page at all; the card says why and links to the vendor's usage page.

connected · needs attention (an error, or the last sync is more than 7 days old) · not connected

Where the numbers come from

  • API-equivalent cost = tokens × the list price for that model (the editable price list). It is what the same usage would cost on the vendor's API: a comparison, not an invoice.
  • Actual billed comes only from vendors that report money; the two figures are always shown separately.
  • Rows from estimated sources are marked est. and never mix silently with exact ones.
  • Local runners are $0, and so are coding-tool requests that name a local backend (Continue + Ollama, Codex OSS models and the like).
  • A model the price list does not know is priced at the fallback row and named in a notice above the KPIs: never guessed silently.

How prices work

Each row of your data is priced by the first rule that fits: the model id is lowercased and normalised (the vendors' spellings of one Claude model become one id); a retired id is priced as its successor (the Model breakdown says priced as …); a platform override — a host's own rate for a model it bills differently from the vendor (Groq, DeepInfra, SambaNova, Together AI, Cerebras) — beats the vendor row for data from that platform; then the first matching row of the API price list wins; a model no row knows falls to the Unknown model row. The bundled list was verified on ; the banner above the list counts the days since. To change a price, edit any cell or add a row in the API price list: edits are stored in this browser only, read user in the list and in the breakdown, and carry no verified date. A platform override is a fixed built-in rate that an edit of the vendor row cannot change — the list says wins for <platform> where that applies.

If something looks wrong

Local collector card says "Not running at http://127.0.0.1:11436"
Start it: node docs/tools/ai-usage-collector.mjs. With --port, put the printed URL in the card's Collector URL field.
Local collector card says "Token rejected"
Paste the token the collector printed; it is also in ~/.ai-usage/collector.token.
Ollama card says "likely CORS"
Set OLLAMA_ORIGINS="*" (or your page origin), restart Ollama, validate again.
Azure / Vertex says "token expired"
Tokens last about an hour: mint a new one with the printed CLI command and paste it again.
The folder picker does nothing
Use Chrome or Edge, the card's "classic folder chooser" link, or skip pickers altogether with the local collector.
Numbers changed after an update
Parsers improve between versions; the first re-scan after an update re-reads the files once.

API price list

    USD per million tokens, editable. A pattern is a regular expression tried against the lowercased model id and its normalised form (claude-opus-4.1 / claude-4.1-opus / claude-opus-4-1-20250805 / the Bedrock anthropic.…-v1:0 and Vertex …@date wrappers all hit one row); the first matching row wins. Retired ids are priced as their successor. A platform override — a host's own rate, listed at the bottom — wins over the vendor row for data from that platform, whatever you set there; such rows say “wins for <platform>”.
    
    
    
  

  

    

    

    
Cache write is billed at the 5-minute-TTL rate where a provider distinguishes TTLs. Anthropic cache reads ≈ 10% of input price; OpenAI cached input ≈ 10%, cache writes free. Edit any cell — totals recalculate instantly.
